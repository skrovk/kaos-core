WHY COPIES EXIST / WHAT IS RESERVED BUT UNUSED IN THIS P4 WORKLOAD
  Node records own live instances, lifetime/access state, the manifest and 8 notification slots.
  Endpoint records own exact current binding identity and lifetime/access state per role.
  Operation scopes stay immutable after cleanup for evidence, authorization and conflict checks.
  Thus current endpoint descriptors and historical operation descriptors have different lifetimes;
  simply replacing immutable scopes with pointers to reusable endpoint slots is unsafe.
  local_facts must remain separate from accepted aggregate evidence: coordinator timing/phase
  guards can reject or delay acceptance of an owner observation.
  record.report[128] is unused: rg report[ in graph_core finds only its declaration.
  In each single-edge P4 record: seven of eight bindings are unused (616 B); all 8 manifest
  ports are unused (64 B); predicate storage is unused (127 B); node request is unused (136 B).
  For 16 retained edge creators these four categories occupy 15088 B, plus 2048 B of unused
  report[] arrays. Much of this is fixed maximum capacity for P5/P6 multi-channel node work.
  In each no-edge node creator, all eight binding slots (704 B) and predicate storage (127 B)
  are unused: 3324 B across four nodes. The 4 spare operation slots reserve 5216 B.
  None of this automatically becomes heap-free when an operation is retired: it remains
  reusable static pool capacity until the compiled layout/limits are changed.

   Illustrative target edge record preserving current non-binding scope fields, omitting

   16 such records would save14080 B before any extra pool/index bookkeeping.
   A union in every existing fixed-size record alone does NOT save space if its largest
   multi-channel-node variant still determines the same maximum size.

   but reduces average supported endpoints from8 to4 pernode; conflicts with desired topology.
