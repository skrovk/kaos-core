# Graph operation test catalogue

Terminology: [shared glossary](graph_operation_glossary.md).

This catalogue specifies future acceptance tests for the [implementation plan](graph_operation_implementation_plan.md). It is not a claim that the tests are implemented or passing. It covers the six operations, every V2 F0–F15/C1–C6 case, the existing finite checks and their witnesses/counterexamples, application examples, and additional implementation hazards. Read the [open questions](graph_operation_design_questions.md) before fixing decision-dependent oracles.

Existing feature implementations may be replaced completely. The oracles below concern protocol behavior, resource bounds and workload meaning; they do not require legacy LOAD compatibility, old guest entrypoint names, a particular codec/runtime, or the existing host patch. Translate fixtures to the selected API/ABI and replace tests tied only to discarded internals. Keep test IDs stable for the formal inventory. Tests motivated by old-code hazards still apply where the same lifetime, identity or overload risk exists in the replacement.

Source abbreviations SH, V2, IN, VN, VG, KD, FT and SIM refer to the plan's linked source register. **D** means described in the materials; **F** means related finite-model coverage exists, not that the concrete test is proved; **G** means a documented implementation/evaluation gap; **N** means an additional explicit test identified in this review. A test can be both F and G when an abstract invariant leaves the concrete mechanism unverified. **U** denotes deterministic core/codec tests, **S** real KaOS simulator tests, **W** application tests, and **H** embedded qualification.

Scope decision on 2 October 2026: [Q05](graph_operation_design_questions.md#q05) accepts possible stale construction after required history is discarded as an implementation limitation and defers a complete prevention mechanism. Preserve reference no-resurrection/at-most-once oracles, but classify that variant as a known limitation/characterization, not a conformance pass. Ordinary deduplication against live/pending/retained records, exact identity checks, bounded resources and memory-safe cleanup remain mandatory. The LIM cases below describe effects to characterize; they do not require implementing every mitigation discussed under Q05.

[Q06](graph_operation_design_questions.md#q06) agrees pressure eviction of the oldest eligible unacknowledged Succeeded/FailedClean report history after reclaiming eligible acknowledged copies; retrieval assertions apply while evidence remains retained. Protect unresolved obligations and current operational state; defer admissions requiring capacity that cannot be reclaimed without discarding protected state. The query contract is provisionally accepted and may be revised during later recovery design. Exercise the agreed policy explicitly rather than assuming either indefinite retrieval or unconditional admission. Rebuilding O's observed view after state loss is recorded as future design work; it does not add recovery tests or guarantees to Q02's baseline.

## Fixtures and common assertions

Q08 scope: cryptographic authentication and security-oriented artifact verification are plan-only. Current tests assume authentic non-Byzantine participants/messages while exercising logical identity/permission checks, parsing, length bounds, assembly and the selected accidental-error recovery checks. Spoofed traffic with otherwise matching metadata is not guaranteed to be rejected. Future security cases must not become mandatory baseline gates or be counted as implemented protections. Length plus CRC32 is the agreed artifact check. O must preserve each recorded opId-to-request association across retries. Devices discard top-level duplicate submissions identified by retained opId state without body comparison or repeated managed work. Preserve CoAP exchange behavior, queries and per-object/action processing; this differs from the reference M1 changed-body-rejection and duplicate-result rules.

Use K0 as live coordinator unless the case explicitly crashes it; K1/K2 own remote endpoints. N is a new instance; A/B/C are complete declared channels, not individual endpoints. Established peers have successfully added runtimes. Keep a running unrelated node U and an unrelated channel Z in every scoped cleanup fixture, and assert their identities, allocations and data service are unchanged by the operation.

The harness must independently pause: admission preflight/reservation, each allocation, preparation completion/publication/acceptance, commit, receiver and sender authorization/activation/report, startup dispatch/execution/STARTED emission/acceptance, cleanup selection/send/owner receipt/stopped/closure/report acceptance, and cutoff handling. Inject lost/delayed/duplicate/reordered **local callbacks as well as network messages**. Capture owner truth and accepted observations separately; owner truth is a test oracle, not hidden knowledge supplied to Kc.

For every applicable test assert: at most one dispatch/execution per addition; no data access before its role is active; no construction after owner-recorded removal; complete cleanup scope; unchanged unrelated objects; no deadline reset; request/creation/instance/owner correlation; bounded allocations including partial work; correct retained history/outcome. Any event gap required for the oracle makes the test inconclusive/failed instrumentation, not a pass. Cleanup timeouts must identify missing objects rather than assert physical leaks or closure.

For the explicit Q05 post-history-discard variant, record violations of the reference no-resurrection/at-most-once properties and resulting application interference as limitation observations. Do not silently apply that exception to tests with retained state, unsafe pointer reuse, misattributed packets, or resource-accounting failures.

Expand each applicable case over outgoing, incoming, co-located and mixed placement, several endpoints on one host, and single- versus multi-service identities. Test both orderings of each two-event race, including same-timestamp events. Use no-fault controls and verify that the fault actually reached the intended boundary. Exercise zero/one/maximum channel counts and `limit−1`, `limit`, `limit+1` for resource/length fields. Exhaustively enumerate small finite predicate inputs and short adversarial schedules; use pairwise parameter coverage and seeded stress at the chosen maximum scale. Record instantiated variants; the row count is not the executed-test count.

## Formal configuration traceability

Q14 requires a TLA+ model and TLC safety/liveness checks for the final event-driven state/transition configuration. Add traceable configurations for the final queue/worker bounds, reserved completion capacity, event/timer service, startup-marker acceptance and ownership/reclamation transitions. Reproduce concurrent admission/preparation, event saturation, cancellation/entry/exit races, delayed callbacks, stopped-but-unreclaimed resources and safe local reclamation while O-authorized distributed removal is unavailable. State temporal properties and fairness/time/delivery/termination assumptions explicitly; preserve Q05/Q08 limitations and Q12's trusted-workload assumption. Check supported progress and Unresolved outcomes where closure remains unavailable. Link model actions to handlers/trace events and reproduce key witnesses/counterexamples as deterministic tests. Retain hashes, bounds, properties, assumptions and run outcomes. Existing finite suites remain reference evidence; they do not yet check this final execution configuration, and no new TLC run is claimed here.

The [CSV inventory](graph_operation_verification_inventory.csv) contains all **90 configurations** from the two suites, including their module, specification, exact expected TLC result, invariants/properties, required trace actions where declared, retained state counts, audit status and target test IDs. No configuration is silently omitted, including the deliberate negative experiments.

The graph suite has 29 positive configurations, 16 negatives and 10 witnesses; the node suite has 19 positives, 7 negatives and 9 witnesses. Positive finite safety is preserved without fairness; conditional progress requires the particular live hosts, scheduling, delivery, resources and time assumptions. The main graph model's coordinators share K0, its examples have one or two operations and at most three channels, and its focused admission/scheduler/reuse models are not a machine-checked composition with C or with the richer node model.

For each witness, turn the retained trace into a deterministic integration schedule and assert the desired behavior while checking conforming invariants. For guard-removal counterexamples, make the corresponding bad state unreachable in core. For liveness-assumption removals, assert the supported safety and uncertainty outcome, not an impossible unconditional completion guarantee. Model mutations stay in verification fixtures and must not ship as disabled production checks.

The forgotten-rejection counterexample has the explicit Q05 implementation disposition: retain its original model result, and characterize the corresponding discarded-history behavior without claiming the stronger invariant was implemented. This scope exception does not alter other guard-removal regressions or authorize test-only guard switches in production.

## Execution and acceptance record

Each instantiated test records ID/variant, setup/profile, applicable requirement, exact boundary/fault, expected result/evidence, trace, actual injected fault, actual result, residual resource obligations, timing/memory measurements, hashes and status: pass, fail, blocked by design, unsupported harness, inconclusive instrumentation, or known limitation characterized. Keep the original reference oracle and any observed violation alongside the Q05 disposition. Do not combine these statuses into one pass count.

Run deterministic codec/core/predicate/lifetime tests on each relevant change; then affected real-process tests with controlled schedules. Run all six operations with no faults before extending to loss/race matrices. Use allocation/sanitizer/churn suites for ownership changes; use selected target-board tests for memory/timing/port claims. Rerun affected TLC configurations when changing a protocol guard or a modeled service algorithm, preserving exact positive/negative/witness expectations. A full sweep is a release gate after those focused checks, not a replacement for them.

Release acceptance requires all mandatory cases and embedded bounds, plus Q14's safety/liveness checks of the final TLA+ state/transition configuration, to pass within the stated scope and assumptions, with Q05's post-history-discard gap explicitly disclosed and characterized where supported. This is not full conformance to the stronger reference no-resurrection guarantee. Q08 leaves cryptographic authentication and security-oriented artifact verification unimplemented; authenticity remains an explicit evaluation assumption, and future security tests are not baseline release gates. Its duplicate-submission discard policy relies on O's immutable opId association and does not implement M1's changed-body detection/rejection or duplicate-triggered result generation; record that disposition separately from conformance to the reference. Q10 requires shorthand rejection tests; shorthand execution/arithmetic tests are deferred. Optional persistence/migration tests receive explicit Q02/Q22 dispositions. Ventilation service acceptance remains separate and needs approved Q20 criteria plus justified Q21 model fidelity. A complete simulator observation with zero useful samples is an experiment result, not successful application service.
